次のステップとして、自分で学習させるのではなく、Hugging Faceで公開されている学習済みの日本語GPT-2の重みを自作GPTに読み込み、これまでと同じ生成と可視化をやってみた。書籍5章にあるOpenAIの学習済みの重みを読み込む話を、日本語の1文字単位モデルでやった形だ。モデルの規模や学習データが桁違いに多いので当たり前ではあるが、生成は自作モデルよりだいぶ文章らしくなった。さらにembeddingやhidden stateの可視化でも、似た文字や同じ話題の単語がまとまる様子も見えて面白かったので書いておく。

学習済みモデルを読み込めるようにした時点のcommitは以下のリンク。gpt.pyのJpCharGPT2が学習済みモデルの構造に合わせたクラスで、import_hf_gpt2.pyがHugging Faceの重みを自作GPTの形に変換している。

### 重みの名前と形を変換して、学習済みGPT-2を自作GPTで動かす
読み込むモデルには、12層・12ヘッド・768次元で、Wikipedia・CC-100・OSCARの171GBで学習されているku-nlp/gpt2-small-japanese-charを選んだ。このモデルは日本語のGPT-2で1文字単位のtokenizerを使っているので、これまで使ってきた1文字1tokenの自作tokenizerにそのまま載せられる。

https://huggingface.co/ku-nlp/gpt2-small-japanese-char

GPT-2の構造はこれまで作った自作GPTとほぼ同じなので、動かすためには次の3点の調整だけで済んだ。

- 重みの名前と形の変換。Hugging Faceの重みはパラメータ名も行列の形も自作GPTと違うので、import_hf_gpt2.pyでダウンロードして自作GPTの形に変換して保存する
- モデル側の調整。GPT-2はQ・K・Vにバイアスがあり、出力ヘッドにtoken embeddingと同じ行列を使う。この2点だけ変えたJpCharGPT2クラスを追加した
- tokenizer側の調整。このモデルの語彙には改行と半角スペースがなく、学習時も除かれている。そこで自作tokenizerでもencodeの前にこの2つを取り除いている

この調整を加えた後、次のコマンドで実際に生成できた。

```bash
# Hugging Faceから重みを取得し、自作GPTの形に変換する
uv run import_hf_gpt2.py
# 変換した学習済みモデルで文章生成をする
uv run main.py generate "日本の首都は" --run-name ku-nlp-gpt2-small-char --temperature 0
```

### 生成は自作モデルよりだいぶ文章らしくなった
temperature 0で生成させると、自作モデルでは一度も出なかった「東京」が出て、そのまま都道府県を重複なく列挙していった。「プログラミングを学ぶには、」も文として自然な続きが出てくる。

```text
# 日本の首都は
日本の首都は、東京都、神奈川県、埼玉県、千葉県、茨城県、栃木県、群馬県、山梨県、新潟県、長野県、富山県、石川県、福井県、岐阜県、…

# プログラミングを学ぶには、
プログラミングを学ぶには、まずは、プログラミングの基礎を学ぶ必要があります。プログラミングの基礎を学ぶことで、プログラミングの基礎を学ぶことができます。…
```

temperature 0.8にしてみても、自作モデルよりかなりそれっぽい文章が出てきていた。

```text
プログラミングを学ぶには、ゲームアプリケーションを作りながら学習することができるので、コンピューターエンジニアになりたいという方にはおすすめの学習方法です。また、ゲームアプリケーションはプログラミング言語として幅広く用いられて…

プログラミングを学ぶには、2年次に自分のペースで学ぶことができました。3年次では、Windowsを使ったPython2のプログラミングの授業を受けました。Python2のバージョンは1.1.0ですので1.1.0を使ってはいけま…
```

### embeddingとhidden stateの可視化では似た文字や同じ話題の単語がまとまっていた
可視化のコマンドはこれまでと同じ。

```bash
uv run main.py visualize-embeddings --run-name ku-nlp-gpt2-small-char
open runs/ku-nlp-gpt2-small-char/embedding_map.html
uv run main.py visualize-hidden-states --run-name ku-nlp-gpt2-small-char
open runs/ku-nlp-gpt2-small-char/hidden_states.html
```

token embeddingの地図は、自作モデルでも文字種が近くに寄る傾向はあったが、学習済みモデルでは漢字・カタカナ・英数字などがはっきり分かれた領域を作っていた。

[f:id:shiba_yu36:20260930131653p:plain]

さらに漢字の中でも似た用語がまとまっている。「県」は府・州・市・国・町、「聞」は聴・耳・見・言のように、同じ場所に入れ替えて使える文字が並ぶ。

[f:id:shiba_yu36:20260930131656p:plain:w300][f:id:shiba_yu36:20260930131658p:plain:w300]

hidden stateの近い文脈は、これまでと同じ銀行・旅行・実行・発行の4文で「行」の位置を見た。Layer 12の近傍には、「行」以外の文字が、それぞれの文の文脈に合った単語の一部として上位に並んでいた。「行」以外の文字だけを抜き出すとこうなる。

| 文 | Layer 12の近傍（「行」以外の文字） |
|---|---|
| お金を預けたい。銀行 | 証券会**社**(0.93) 金融機**関**(0.93) ネットバン**ク**(0.93) 消費者金**融**(0.92) |
| 休暇を楽しもう。旅行 | ジェットツーリン**グ**(0.95) スキーツア**ー**(0.94) 海外留**学**(0.94) |
| 処理が完了した。実行 | 起**動**(0.95) スキャ**ン**(0.94) インストー**ル**(0.94) |
| 書類を受領した。発行 | 実**施**(0.94) 出**版**(0.94) 発**券**(0.93) |

銀行は金融系、旅行は旅系、実行はソフトウェア操作系、発行は書類系と、同じ「行」という文字より、同じ話題で同じ働きをする単語の末尾のほうが近い。「どの文字か」ではなく「どんな話題のどんな単語か」でまとまっている雰囲気がはっきり見えた。
