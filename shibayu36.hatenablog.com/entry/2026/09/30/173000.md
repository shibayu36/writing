### ヘッドを分ける実装は、1ヘッドのAttentionを並べて連結するだけだった
書籍を読んでいたときはMulti-Head Attentionが何をしているのか追えなかった。しかし実装してみると1ヘッドのCausalAttentionを幅を狭くしてn_heads個並べ、出力を連結しているだけだった。

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_in: int, d_out: int, context_length: int, n_heads: int) -> None:
        super().__init__()
        head_dim = d_out // n_heads
        heads: list[nn.Module] = []
        for _ in range(n_heads):
            heads.append(CausalAttention(d_in, head_dim, context_length))
        self.heads = nn.ModuleList(heads)
        self.out_proj = nn.Linear(d_out, d_out)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        outputs: list[torch.Tensor] = []
        for head in self.heads:
            outputs.append(head(x))
        context_vec = torch.cat(outputs, dim=-1)
        return self.out_proj(context_vec)
```

W_query・W_key・W_valueがヘッドごとに別なので各ヘッドは違う位置を注目先として選べる。最後のout_projは横に並んでいるだけの各ヘッドの出力を混ぜ合わせる線形層だ。

```text
torch.cat の出力（128次元）: 各ヘッドの32次元が横に並んでいるだけ
[ head0の32次元 | head1の32次元 | head2の32次元 | head3の32次元 ]
                          ↓ out_proj（128×128の線形層）
[ 4ヘッドの結果をすべて混ぜ合わせた128次元 ]
```

書籍に載っている、1つの大きな行列をviewとtransposeでヘッドに切り分ける方式も作ってみた。しかし構造を理解するには並べる形のほうが読みやすく、この規模だと速度も変わらなかった。理解しやすさを優先して、先ほどの実装のまま実験をしていった。

### 4ヘッドにしてもlossも生成もほぼ変わらなかった
前回と同じ4層・128次元・5,000stepのまま、config.pyのn_headsだけを1と4にして学習した。学習と生成のコマンドはこんな感じ。

```bash
# 学習する
uv run main.py train --run-name l4h4
# 学習したモデルで文章生成をする
uv run main.py generate "プログラミングを学ぶには、" --run-name l4h4 --temperature 0
```

全バッチのvalidation lossは1ヘッドが3.107、4ヘッドが3.095で、差は0.013しかなかった。層を1から4にしたときは0.31下がっていたので桁が違う。

生成もどちらが良いとは言えなかった。temperature 0で「プログラミングを学ぶには、」の続きを生成させるとこんな感じ。

```text
# 1ヘッド
プログラミングを学ぶには、その後の人がいるということがあります。
それは、それは、その人がいつも、それぞれの人にも、それぞれの人にもなっているのです。
それは、それぞれの人がいいということです。

# 4ヘッド
プログラミングを学ぶには、学習塾の学習を学びたいという。
学習塾の学習については、学習塾の学習を行うことができる。
学習塾の学習については、学習塾の学習を学習する。
```

### Attention weightを可視化すると、直前の文字に強く注目するヘッドがあった
lossではヘッドごとの最終学習状態が見えないので、同じ入力で各ヘッドがどの文字に注目しているかを可視化してみた。attention weightはある文字を処理するときに前のどの文字にどれだけ注目したかの割合だ。ヘッドごとに並べれば「直前の文字に注目するヘッド」「文の先頭に注目するヘッド」のような分担があるかが分かるはず。各ヘッドに入る入力をhookで取り出してQとKからattention weightを計算し直し、層ごとにヘッドのヒートマップを並べたHTMLを作る。

```bash
uv run main.py visualize-attention --run-name l4h4
open runs/l4h4/attention_weights.html
```

縦軸が今の文字、横軸が注目した文字で、色が濃いほど重みが大きい。「銀行の口座を開く」の「行」が「銀」にどのくらい注目しているか、といったことが読める。

下のスクショではLayer 2のHead 3が直前の文字に0.8くらいの重みを置いていて、対角線のすぐ左だけが濃い。他の3つのヘッドはどれもぼんやり全体に注目していて、何を分担しているのかは今回の規模ではよく分からなかった。それでもヘッドがどこに注目しているかをこうやって覗ける手法自体は面白かった。

### まとめ
ヘッドを4つにしてもこの規模ではlossと生成に差が出ず、可視化でも直前の文字に注目するヘッド以外の役割は分からなかった。ただ自分で実装してみたら、書籍3章を読んでも追えなかったMulti-Head Attentionがようやく理解できた。解釈には素人の推測も混ざっているので間違っていたらツッコミをもらえると嬉しい。
