最近AIエージェントを開発していてLLMの中身を少しでも知っておきたいと思うようになった。なぜなら、ある技術を使うだけだったとしても基礎を理解していると応用に繋げられた経験があるためだ。MySQLのパフォーマンスチューニングをするときもインデックス構造を知っていたことでうまくチューニングできた。

今は次のような質問に全く答えられないので、仕組みを理解した上で答えられるようになりたい。

- コンテキストが長いほど精度が落ちたり、最初の方を忘れたりするのはなぜか
- プロンプトキャッシュは何をキャッシュしているのか
- fine-tuningでは何が変わっているのか

実装してみて理解するのが一番速いと思ったので、GPT-2のアーキテクチャを元に実装しながら理解を進める『つくりながら学ぶ！LLM 自作入門』を読み始めた。

[asin:4839987807:detail]

ただ、2章のtoken embeddingまでは理解できたが、3章のAttentionあたりや4章のGPTモデルの実装で理解できなくなってしまった。Q・K・VやMulti-Head Attentionなどの概念が一気に出てきて、Transformerが結局何をしているのか追えなくなった。また実際に訓練して文章生成してみるために5章を終わらせないといけなかったため、動かしながら理解するやり方が取れなかったのも一因だと思う。

そこでもっと小さくステップを刻むため、1層1ヘッドの最小構成をClaude Codeと一緒に作り、学習から生成までを先に動かしてみた。これでかなり理解が進んだのでその過程を書いておく。

### 1層1ヘッドの最小構成で日本語データを先に学習・生成させてみる
Claude Codeと一緒に作ったのは、Transformerブロックが1層でattention headが1つ、tokenは1文字1tokenという構成のGPTだ。さらに訓練データに日本語を使いたく、[FineWeb2 Edu Japanese](https://huggingface.co/datasets/hotchpotch/fineweb-2-edu-japanese)から一部を使うことにした。

この構成にすることで、バイトペアエンコーディング・Multi-Head Attentionなどの概念を一旦後回しにして、訓練から文章生成まで先に動かせる。また日本語を使うことで、生成した文が「それっぽいか」の細かいニュアンスを理解しやすくなる。

1層1ヘッドまで実装した時点のcommitはこちら。

https://github.com/shibayu36/learn-llm/tree/c8b9c147c6a6a9c975d118b258a7426cbba6340e/llms-from-scratch

1層1ヘッドの実装は、gpt.pyのOneLayerOneHeadGPTから追いかければ分かると思う。また1tokenの次元数やコンテキスト長、パラメータ更新回数はconfig.pyで設定できる。

実際に動かす方法はこんな感じ。

```bash
# 訓練データをダウンロード
uv run prepare_data.py
# 訓練する
uv run main.py train --run-name l1h1
# 学習したモデルで文章生成をする
uv run main.py generate "日本の首都は" --run-name l1h1 --temperature 0
uv run main.py generate "日本の首都は" --run-name l1h1 --temperature 0.8
```

実際に学習を進めながら「日本の首都は」に続く文を生成させてみた時の様子は次のとおり。最初はデタラメな文字の羅列だったが、少しずつ文の形を作っているのが分かる。このGPTの規模でこの程度の学習量だと「日本の首都は」に続く文としては全然うまくいってないが、それでもどんなことをしているかのイメージはついた。

```text
step 0:    敏歌霞榴酢米蛋泰措罷購燥端秒渉…
step 200:  、ートのです。 - ートにようのです。 そのです。 そのです。…
step 400:  、1000000000000000000000000000…
step 1000: 、そのですることが、そのです。 そのできるのでする。…
step 2400: 、その中です。 これまためには、その中には、その中のためには、…
step 5000: 、その中についているのです。 これは、その中には、それているというということができる。
```

### token embeddingの様子を可視化してみる
出力だけでなく、学習の結果モデルの中身がどうなったかを可視化したかった。token embeddingの様子を2次元にマッピングして可視化する手法があるようなので、その実装をしてみた。

```bash
# token embeddingを可視化するHTMLを作る
uv run main.py visualize-embeddings --run-name l1h1
# ブラウザで開く
open runs/l1h1/embedding_map.html
```

2次元に可視化した様子はこちら。64次元を2次元に落としているため、実際には2次元上で近いほど類似しているわけではないのだが、ひらがな・カタカナ・英字・漢字・数字がなんとなく近い位置に配置されている様子が分かる。

[f:id:shiba_yu36:20260928091954p:plain]

ある文字をクリックすると実際の類似度が右下に表示される。これによると「長」という文字は「短」や「老」など、なんとなく日本語的に似ている文字と同じグループになっていそうだ。

### まとめ
前提知識が足りなくて書籍の順番通りにやると理解が難しかったのだが、もっとシンプルなものをClaude Codeと一緒に実装し動かすことでLLMに対する理解を深めることができた。LLMの理解をしたいが一歩目につまずいている人は、1層1ヘッドで日本語を学習させるやり方がオススメ。冒頭に挙げた疑問に答えられるようになるにはまだ遠いが、次はここから層やヘッドを増やしつつ書籍の3〜4章に戻って理解を進めていきたい。
