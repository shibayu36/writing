最近はClaude CodeやCodexを複数セッション並行で動かしている。すると完了通知が来ても、どのセッションが何を終えたのか通知からさっと把握できないし、通知をクリックしても該当の画面に戻れない。デフォルトの通知機能ではこのあたりをカスタマイズできないので、hooksから呼ぶ通知スクリプトを自作していい感じにした。

具体的には、通知の本文にエージェントの直前の返信を表示し、通知をクリックすると起動元のターミナルやアプリを開くようにした。さらに複数エージェントをpaneに並べて動かせる[herdr](https://herdr.dev/)上のセッションなら、該当paneまでフォーカスする。

スクリプトはconfig-fileリポジトリに置いてある。

### Claude CodeとCodexのhooksから同じ通知スクリプトを呼ぶ

仕組みは、Claude CodeとCodexそれぞれのhooksから、同じnotify-end.shを呼ぶだけの構造だ。通知には[alerter](https://github.com/vjeantet/alerter)を使う。alerterは通知がクリックされたかどうかを受け取れるので、クリック時の復帰処理を仕込める。

```sh
brew install vjeantet/tap/alerter
```

Claude Code側は`~/.claude/settings.json`のNotification hookに設定する。

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "permission_prompt|auth_success|elicitation_dialog|idle_prompt",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/scripts/notify-end.sh claude"
          }
        ]
      }
    ]
  }
}
```

matcherのidle_promptは、応答完了後しばらく放置しているセッションだけを通知の対象にできる。

Codex側は`~/.codex/hooks.json`のStop hookに設定する。

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/scripts/notify-end.sh codex"
          }
        ]
      }
    ]
  }
}
```

呼ばれるnotify-end.shの全体はこれ（記事用にデバッグログ周りは省いている）。以降でポイントを解説する。

```sh
#!/bin/bash

# 第1引数で通知元アプリを指定（claude / codex）。省略時はclaude
APP="${1:-claude}"
case "$APP" in
  codex)
    TITLE="Codex"
    SOUND="Submarine"
    ICON="https://avatars.githubusercontent.com/u/14957082?v=4"
    ;;
  *)
    TITLE="Claude Code"
    SOUND="Glass"
    ICON="https://cdn.prod.website-files.com/6889473510b50328dbb70ae6/68c33859cc6cd903686c66a2_apple-touch-icon.png"
    ;;
esac

# 標準入力からhookのInputデータを読み取り
INPUT=$(cat)

# 直前のassistantメッセージから通知テキストを組み立てる
build_message() {
  # CodexのStop hookはlast_assistant_messageをhook inputに直接含むため、transcriptを読まずに使う
  LAST_MSG=$(echo "$INPUT" | jq -r '.last_assistant_message // empty' 2>/dev/null)
  if [ -n "$LAST_MSG" ]; then
    echo "$LAST_MSG" | tr '\n' ' ' | sed 's/^[[:space:]]*//;s/[[:space:]]*$//' | cut -c1-100
    return
  fi

  TRANSCRIPT_PATH=$(echo "$INPUT" | jq -r '.transcript_path')
  if [ ! -f "$TRANSCRIPT_PATH" ]; then
    echo "Task completed"
    return
  fi

  # hook発火時にはtranscript書き込みが完了していないことがあるため、sleepで待機
  sleep 1

  # Claude Codeはtranscriptの最後のassistantメッセージから、contentのtypeに応じて通知テキストを取得
  #   text → .text
  #   tool_use → Bash: .input.description / AskUserQuestion: .input.questions[0].question
  #              Write/Edit: "Edit: " + file_path
  #   それ以外 → スキップ
  MSG=$(tail -30 "$TRANSCRIPT_PATH" | \
        jq -r '
          select(.message.role == "assistant") |
          .message.content[0] |
          if .type == "text" then
            .text
          elif .type == "tool_use" then
            if .name == "Bash" then (.input.description // empty)
            elif .name == "AskUserQuestion" then (.input.questions[0].question // empty)
            elif .name == "Write" then "Edit: " + (.input.file_path // empty)
            elif .name == "Edit" then "Edit: " + (.input.file_path // empty)
            else empty
            end
          else
            empty
          end
        ' 2>/dev/null | tail -1 | tr '\n' ' ' | sed 's/^[[:space:]]*//;s/[[:space:]]*$//' | cut -c1-100)

  echo "${MSG:-Task completed}"
}

notify_and_handle_click() {
  MSG=$(build_message)

  # 同一セッションの古い通知は新しい通知で置き換える
  SESSION_ID=$(echo "$INPUT" | jq -r '.session_id // empty')
  SESSION_DIR=$(basename "$(pwd)")
  GROUP="notify-end-${APP}-${HERDR_PANE_ID:-${SESSION_ID:-$SESSION_DIR}}"

  ACTIVATION_TYPE=$(alerter \
    --title "$TITLE" \
    --message "$MSG" \
    --sound "$SOUND" \
    --app-icon "$ICON" \
    --group "$GROUP" \
    --timeout 3600 \
    --json | jq -r '.activationType // empty')

  [ "$ACTIVATION_TYPE" = "contentsClicked" ] || return

  # ターミナル起動時は__CFBundleIdentifierに起動元アプリのbundle idが入っている。
  # GUIアプリ起動時は未設定のため、APPから起動元(ChatGPTアプリ / Claude Desktop)を推定する
  if [ -n "${__CFBundleIdentifier:-}" ]; then
    BUNDLE_ID="$__CFBundleIdentifier"
  elif [ "$APP" = "codex" ]; then
    BUNDLE_ID="com.openai.codex"
  else
    BUNDLE_ID="com.anthropic.claudefordesktop"
  fi
  open -b "$BUNDLE_ID"

  # herdr内のセッションなら該当paneへフォーカスする
  if [ -n "${HERDR_PANE_ID:-}" ]; then
    herdr agent focus "$HERDR_PANE_ID"
  fi
}

# alerterはクリックまたはタイムアウトまでブロックするため、hook自体は即座に終了させる
notify_and_handle_click </dev/null >/dev/null 2>&1 &
```

### 通知文は直前の返信から組み立てる

まず「通知から何をしたのか分からない」問題は、エージェントの直前の返信を通知本文に入れることで解決した。

Codexは楽で、Stop hookのinputに`last_assistant_message`として直前の返信がそのまま入っているので、これを使うだけ。

Claude Codeにはこのフィールドがないので、hook inputの`transcript_path`から会話ログ（JSONL）を読み、最後のassistantメッセージをjqで取り出す。応答がテキストで終わらず、コマンド実行の許可待ちなどツール実行で止まっていることもある。その場合はBashなら実行内容のdescription、AskUserQuestionなら質問文、Write / Editなら編集先のファイル名を通知文にしている。

これで通知を見るだけで、修正を終えたのか、許可待ちで止まっているのか、何か質問されているのかがさっと分かるようになった。

### クリックで起動元の画面に戻る

次に「通知をクリックしても該当画面に戻れない」問題。alerterに`--json`を付けると、通知がクリックされたのかタイムアウトしたのかがJSONで返ってくるので、クリックされていたら復帰処理を行う。

復帰先は次のように判定している。

- ターミナルから起動したセッションなら、環境変数`__CFBundleIdentifier`に起動元ターミナルのbundle idが入っているので、`open -b`で開く
- Claude DesktopやChatGPTアプリから起動した場合は`__CFBundleIdentifier`が無いので、claude / codexどちらの通知かでアプリを推定して開く
- さらにherdr上のセッションなら環境変数`HERDR_PANE_ID`が入っているので、`herdr agent focus`で該当paneまでフォーカスする

これで、herdrで並べた複数セッションのうちどれかが終わった時も、通知をクリックするだけでそのpaneに一発で戻れる。

1つハマったポイントがある。alerterはクリックかタイムアウトまでプロセスがブロックし続けるので、そのままだとhookコマンドが終了せずClaude Code側の処理を待たせてしまう。そこで通知処理全体をバックグラウンドに逃して、hook自体は即座に終了させている。

### まとめ

こんな感じで、何をしたかが分かる通知が来て、クリックで該当画面へすぐ戻れるようになった。複数のAIエージェントを並行で動かしていても「どれが終わったんだっけ」と探し回ることがなくなり、かなり快適になった。ぜひ真似してみてほしい。
