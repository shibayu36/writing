GitHubでPull Requestを作った瞬間に、Claude Code Actionを使って最低限セキュリティレビューをさせる仕組みを導入したいことがあった。またこの仕組みは特定リポジトリだけでなく、他のリポジトリにも簡単に展開していきたいと考えていた。

このときどうやって他リポジトリに展開しやすくしておくか悩んだが、Skillを別リポジトリで共通化しつつ、GitHub Actionsのステップで`gh skill install`してから実行することで解決した。今回はこの話について紹介する。

### 課題: 展開しやすさのためSkillで共通化したいが、CIでしか使わないSkillを利用側にコミットしたくない

レビュー観点をワークフローのプロンプトに直書きすると、展開のたび同じプロンプトをコピーすることになる。観点を直した時に全部に反映して回るのも面倒だ。なのでレビュー観点はSkillとして切り出し、別リポジトリにまとめておきたい。例えばmy-company/agent-skillsというリポジトリを用意し、その中にmy-company-security-reviewというSkillを置いておくイメージだ。

悩んだのはその先で、共通化したSkillを使う側にどう置くかだった。Skillを使いたいとき、通常は`gh skill install`などでプロジェクト配下にインストールし、リポジトリにコミットすることが多い。しかし今回Skillを使うのはCIのワークフローの中だけで、それだけのためにSkillのファイルを各リポジトリにコミットし、メンテナンスし続けるのもだるい。

### CIのステップでgh skill installしてからClaude Code Actionを動かす

そこで、必要なSkillをワークフローの実行時にインストールして使うことにした。

今回やりたいPRへの自動セキュリティレビューには、2つの能力が必要になる。セキュリティの観点をもとにレビューする能力と、PRのdiffを取得したりコメントを投稿したりする能力だ。そこでこの2つをSkillとして用意し、ワークフローの中でインストールする。

- `my-company-security-review`: 社内向けに用意したセキュリティレビューの観点
- `github-pr-review-operation`: PRのdiff取得やインラインコメント投稿をやってくれるSkill。https://blog.shibayu36.org/entry/2025/12/17/173000 で作ったものをそのまま使っている

ワークフローはこんな形になっている。

```yaml
      - name: Install skills
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token }}
        run: |
          gh skill install my-company/agent-skills my-company-security-review \
            --agent claude-code --scope user
          gh skill install shibayu36/agent-skills github-pr-review-operation \
            --agent claude-code --scope user

      - name: Run Claude Security Review
        uses: anthropics/claude-code-action@v1
        with:
          github_token: ${{ steps.app-token.outputs.token }}
          claude_args: |
            --allowedTools Read,Grep,Glob,Bash(gh:*),Skill(github-pr-review-operation),Skill(my-company-security-review)
          prompt: |
            # 手順
            1. github-pr-review-operation スキルを使って対象PRの diff を取得する
            2. my-company-security-review スキルを実行し、取得した diff に対するセキュリティレビューの指摘を得る
            3. 検出した各指摘を、該当行への インラインコメント として投稿する
            4. 加えて 短い総評コメント1件 をPRに投稿する
```

レビューの観点や具体的なPR操作の手順はSkill側に書かれているので、ワークフローに書くプロンプトはどのSkillをどの順番で使うか指示する程度で済む。

インストールに使っている`gh skill`はGitHub CLIのSkill管理コマンドで、GitHubリポジトリに置いたSkillをインストールできる。まだpreviewの機能だが、GitHub Actionsのランナーには最初から`gh`が入っているため、追加のセットアップなしですぐ使えるのが良い。

注意点がいくつかある。

- `--scope user`でインストールする必要がある。Claude Code ActionはPR上で動くとき、セキュリティのため作業ディレクトリの`.claude/`配下などをPRのbaseブランチのもので置き換える。そのためprojectスコープで`.claude/skills/`にインストールしたSkillは消えてしまう。userスコープならこの問題が起こらないことが分かった
- Skillはインストールしただけでは呼び出せないので、`--allowedTools`に`Skill(github-pr-review-operation)`のように書いておく必要がある
- privateリポジトリのSkillを入れるなら、`GH_TOKEN`にそのリポジトリへのアクセス権が必要。自分の場合はGitHub AppのトークンにSkillリポジトリも含めて発行している

これで、最初に出した「展開しやすさのためSkillで共通化したいが、CIでしか使わないSkillを利用側にコミットしたくない」という課題を解決することができた。

### まとめ: 他のリポジトリにはワークフローを置くだけで導入できる

この構成にしたことで、他のリポジトリでもセキュリティレビューを入れたくなったら、簡単なワークフローを1つ置くだけでよくなった。長大なレビュー観点のプロンプトをリポジトリごとにコピーして回らずに済むのが嬉しい。

同じように、Skillで共通化しつつリポジトリにはコミットしたくないケースがあれば、このやり方を使ってみてほしい。
