自分の設定ファイルやインストールするアプリは、https://github.com/shibayu36/config-file のリポジトリで管理している。これまでは私物Macと仕事Macが全く同じになるように、雑にsymlinkを張るスクリプトで運用していた。新しい仕事用のMacをもらったのをきっかけに、私物だけ・仕事だけに入れるものをちゃんと分けつつ、セットアップの自動化の度合いも上げたくなった。そこでsymlinkで張る今の使い方を変えずに済むmise bootstrapを採用した。

### これまでの管理方法

リポジトリで管理していたのはパッケージ群・dotfiles群・Mac設定群の3種類で、それぞれ別のファイルに書いて反映していた。

```sh
# パッケージ群: Brewfileに書いてbrew bundleで入れる
brew "git"
cask "ghostty"
mas "Amazon Kindle", id: 302584613

# dotfiles群: auto-config.shにln -sを並べて張る
ln -s ~/development/config-file/.zshrc ~/
ln -s ~/development/config-file/.gitconfig ~/

# Mac設定群: macos-defaults.shにdefaults writeを並べて実行する
defaults write NSGlobalDomain KeyRepeat -int 2
defaults write NSGlobalDomain InitialKeyRepeat -int 15
```

大きく困ってはいなかったが、スクリプトが3つに分かれていて冪等でもなく、私物と仕事で入れるものを分ける場所もなかった。たとえば私物にだけ入れたいアプリがある、私物と仕事で一部dotfilesを分けたい、などがしづらかった。

いくつかツールを調査したところmise bootstrapを採用することにした。

### mise bootstrapを選んだ理由

2026年6月、miseに[mise bootstrap](https://mise.jdx.dev/bootstrap.html)という機能が入った。パッケージ・dotfiles・macOS defaultsを1つのconfig.tomlに宣言しておくと、`mise bootstrap`1コマンドで差分を適用してくれる。

mise bootstrapはdotfilesをsymlinkで張るのがデフォルトで、私物・仕事ごとの設定ファイルも重ねられる。マシンごとにファイルの中身を少し変える機能もある。ランタイム管理でmiseをすでに使っていたので道具が増えないのも良かった。

同様の課題を解決してくれるようなchezmoiやNixも調査したが、mise bootstrapはシンプルで自分の使い方にも合いそうと思ったので採用した。

### 共通・personal・workの設定をenvで切り替える

miseは`~/.config/mise/miserc.local.toml`の`env`に書いた名前の`config.<env>.toml`を、共通のconfig.tomlと合わせて読む。そこで私物Macと仕事Macの両方へ同じ4ファイルを置き、`miserc.local.toml`の`env`だけをMacごとに変えている。

[f:id:shiba_yu36:20261011162746p:plain]

共通のconfig.tomlにはこれまで3つのスクリプトに分かれていたものを書く。

```toml
[bootstrap.packages]
"brew:git" = "latest"
"brew-cask:ghostty" = "latest"
"mas:302584613" = "latest" # Amazon Kindle

[dotfiles]
"~/.zshrc" = { source = "~/development/config-file/.zshrc" }
"~/.gitconfig" = { source = "~/development/config-file/.gitconfig" }
"~/Library/Application Support/lazygit/config.yml" = { source = "~/development/config-file/lazygit/config.yml" }

[bootstrap.macos.defaults.NSGlobalDomain]
KeyRepeat = 2
InitialKeyRepeat = 15
"com.apple.swipescrolldirection" = false
```

personalとworkにはそれぞれでだけ入れるものを書く。たとえば1PasswordとChromeは仕事Macだと会社管理で自動的に入るので、work側には入れずpersonal側にだけ書いている。Google Driveのアプリは仕事Macでのみ使うのでwork側にだけ書いている。

```toml
# config.personal.toml
[bootstrap.packages]
"brew-cask:1password" = "latest"
"brew-cask:google-chrome" = "latest"
```

```toml
# config.work.toml
[bootstrap.packages]
"brew-cask:google-drive" = "latest"
```

あとは`mise bootstrap`を実行すればパッケージ・dotfiles・Mac設定がまとめて反映される。日々の同期も`git pull`して`mise bootstrap`するだけで、宣言との差分だけが適用される。

### まとめ

こんな感じで、私物と仕事で共通の設定とそれぞれの設定を分けつつ、セットアップが`mise bootstrap`1コマンドになった。新しいMacのセットアップがだいぶ楽になって満足している。symlinkとスクリプトくらいの運用で複数のMacを持っている人には、ちょうどいいと思う。
